# Remember That Thing — продуктовый бриф

## Идея

Приложение, в котором пользователь сохраняет товары, которыми пользовался, со своей оценкой, комментарием, категорией и фото. Главная проблема, которую оно решает: помочь вспомнить у полки, насколько хорош или плох был товар, который нужно купить сейчас.

Сценарии: домохозяйка запоминает производителей колбасы, полотенец, подгузников; ценитель вин ведёт коллекцию; студент запоминает канцелярию.

Ключевой пример: жена просит купить «такое же оливковое масло, как в прошлый раз». С приложением она создаёт список покупок и делится им; в списке есть и просто текст («хлеб»), и товары из её базы с фото и оценкой.

Монетизация: семейная подписка, шаринг заметок с друзьями.

## Позиционирование относительно конкурентов

- Прямые конкуренты (WasOK, Scan It Rate It, RateBud, Rate Anything, Rate It: Rank Anything) — маленькие инди-приложения, почти все хранят данные только локально, без совместного доступа.
- Списки покупок (AnyList, Bring!, Listonic, OurGroceries) — отличный совместный доступ, но нет личных оценок и базы товаров.
- Вертикальные приложения (Vivino, Untappd, CellarTracker) — сильны в своих нишах, в лоб с ними не конкурируем.
- Наше отличие: общая семейная база оценённых товаров + общий список покупок, где пункт ведёт к конкретной карточке товара.
- Фокус на старте: семейные покупки. Ценители и студенты — позже.

## Стек

- Клиент: React Native + Expo, TypeScript. Один код для iOS, Android и web. Тестирование на телефоне через Expo Go.
- Бэкенд: Supabase (Postgres, auth, storage, edge functions).
- Сканер штрихкода: нативный, через expo-camera (сканирует полоски в реальном времени, без фото и без OCR). Резерв — ручной ввод цифр. Проверять контрольную цифру EAN-13.
- Распознавание товара по фото: мультимодальная ИИ-модель (дешёвая/быстрая), вызывается ТОЛЬКО с сервера (edge function). API-ключ никогда не попадает в клиент.

## Модель данных (ключевые решения)

- **Два слоя данных о товаре:**
  - Общая карточка товара (одна на всех): бренд, название, вес/объём, фото, системная категория, атрибуты, штрихкоды.
  - Личный слой пользователя: оценка, комментарий, личные категории/теги, где купил, цена, личные фото. Видят только владелец и те, с кем он поделился.
- **У товара может быть несколько штрихкодов** (разные объёмы, старый и новый код после редизайна).
- Товары без штрихкода (весовые, вино в ресторане) тоже поддерживаются — через фото и ручной ввод.
- Вино: год урожая — отдельное поле (код между урожаями обычно не меняется).
- Правки общей карточки от одного пользователя не должны сразу менять её для всех (нужна проверка/модерация).

## Поиск по штрихкоду и кеш

1. Клиент отправляет на сервер только цифры кода.
2. Сервер ищет: своя база → открытые базы (Open Food Facts) → не найдено.
3. Найдено → возвращается карточка, фото не нужны.
4. Не найдено → пользователь фотографирует лицо (обязательно) и оборот (по желанию) → сервер вызывает модель → черновик карточки (JSON: бренд, название, вариант, вес, категория, производитель) → пользователь подтверждает/правит → карточка сохраняется в общую базу.
5. Следующий пользователь с этим кодом получает карточку мгновенно и бесплатно. Затраты на ИИ растут с числом уникальных товаров, а не пользователей.

Open Food Facts: лицензия CC BY-SA / ODbL — проверить условия перед смешиванием с нашей базой.

## Категории и языки

- Категория — это ID, а не название. У системной категории есть переводы (ru, uk, ro, en, ...).
- Основа дерева: стандартная таксономия (Google Product Taxonomy для широты + Open Food Facts для еды), упрощённая.
- Два уровня: системная категория (назначает модель автоматически, обеспечивает совпадение между пользователями) и личные категории/теги на любом языке, связываемые с системными (подсказка «это похоже на …»).
- Свойства вроде «солёные», «без сахара» — атрибуты, а не подкатегории. Категория отвечает на «что это?», атрибут — на «какое оно?».
- Раздельные настройки: язык интерфейса (по умолчанию системный) и язык контента.

## Фото

- Источник фото общей карточки — пользователи (первое фото лица товара).
- Перед публикацией в общую карточку: вырезать объект с фона (сегментация на устройстве), оригинал остаётся в личном слое.
- Хранить сжатые версии: ~800 px по длинной стороне, WebP, + миниатюра для списков.
- Модерация: модель проверяет, что на фото упаковка товара.
- Фото общей карточки можно обновлять (редизайн упаковки).
- Раздача через CDN / хранилище без платы за исходящий трафик.
- Приватность: фото уходят стороннему провайдеру ИИ — указать в политике конфиденциальности.

## Первая сессия (FTUE)

1. Экран-приглашение «Добавь первый товар» → кнопка сканера + «Нет штрихкода».
2. Перед системным запросом разрешения на камеру — свой поясняющий экран.
3. Сканер ловит код сам (вибрация), цифры пользователю не показываем; запрос на сервер в фоне с анимацией «ищем…».
4. Найден → «Это он?» с готовым фото. Не найден → фото лица (оборот опционально; распознавание лица запускается сразу после снимка).
5. Один экран: фото + предзаполненные бренд/название/категория + звёзды + комментарий → «Сохранить». Обязательна только оценка.
6. Каталог с первым товаром + подсказка: «В магазине просто наведи камеру на товар — и увидишь свою оценку».

Принцип: одна кнопка Scan для всего. Если товар уже в базе пользователя — сразу показать его оценку и комментарий; если нет — начать добавление.

## Каталог товаров

- Строка: фото слева; справа крупно название, под ним мелко бренд и категория; рейтинг справа.
- Поиск показывать, когда товаров больше ~5.

## Навигация (табы снизу)

Профиль (временно) | Товары | **Scan** (центр) | Списки покупок | Настройки

- Настройки и профиль позже могут уехать в плавающие кнопки.
- Кандидат на освободившееся место: лента друзей и семьи («Богдан оценил…», «Жена добавила в список…»).

## Открытые вопросы

- Содержимое настроек.
- Авторизация: можно ли начать анонимно и завести аккаунт позже (для синхронизации и шаринга).
- Модель модерации правок общих карточек.
- Механика семейной подписки и шаринга.
- Выбор провайдера ИИ-модели и схема JSON-ответа.
